# 批量采集与失败隔离修复 — 2026-10-30

前置代码：`6eb12382b6183a43ec4ce43259c94ea73e55c12e`。前置公开版本：17,207 条履历事件、4,509 名人员、351 条去重人才关系、366 个评分端点。它们是已观测记录，不是世界总体分母。

## 修改依据与实现

逐人 EntityData 读取把网络往返放大为每人一次。当前运行环境实测官方 `wbgetentities` claims/info 接口返回 200，2 个实体、54,453 字节、1.640 秒，包含各实体 revision；没有保存原始响应。随后接入每批至多 10 个 ID、2 MiB 响应上限的正式只读 API。保留原有单实体通道；只有响应过大才能使用它回退，拒绝、限流、maxlag 不回退。每人事务、日期/学位/岗位的证据标准、ORCID 稳定标识后续候选规则由同一个提交函数负责，没有提高证据等级。

批量成员同时记录整批原始响应哈希与单实体规范 JSON 哈希，两者有明确标签。未保存原始 JSON/XML/档案；个人级结构化输入留在 D 盘外部目录。既有 EntityData 快照不被重抓或改写。

本轮发现阶段时间耗尽被误记为成员失败，增加重试等待。现在连接、读取、请求间隔及候选发现窗口由 `StageDeadline` 明确区分。真正提前发生的网络超时和服务端暂停仍保留失败/限流语义；ORCID 任一章节未完成时，整人输入回滚。

## 红蓝复测与回归

Python 191 项通过；前端 Node 30 项通过。首次全量回归暴露资源计量测试依赖全仓库正在增长的日志，导致字节差断言不稳定；该单元测试已隔离到自己的项目产物夹具，生产资源计量未被放宽。首次 CLI 兼容性测试暴露旧 Namespace 没有 batch_size，已保留兼容默认值。首次失败日志均保留。OOD 和发布后的浏览器、哈希、复现结果见配套最终验收记录。
